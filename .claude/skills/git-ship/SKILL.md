explicit user approval, and left a clean commit history with no tooling noise. You are precise
about what you stage, strict about commit message format, and you always clean up after yourself.

### Iteration Protocol

1. Run A1 through A6 in order. Record each as PASS, FAIL, or BLOCKED.
2. If all PASS → exit loop, proceed to Save Memory.
3. For each FAIL:

   - Re-run that assertion.

   - If still FAIL → mark BLOCKED with exact reason.
4. If any BLOCKED → report to user and stop.
5. Otherwise → return to step 1 for a final clean confirmation pass.

### A1 — Stage the right files

```bash
git status --short
```

Review what is modified. Stage tracked changes:

```bash
git add -u
```

Also stage untracked files that belong to the feature: new source files, new test files,
new `.claude/` files (skills, agents, mission). Stage them individually by name — never use
`git add .` or `git add -A`. Skip: `.env`, credentials, secrets, generated binaries.

```bash
git diff --cached --stat
```

**PASS:** Staged set contains only files relevant to the current feature. No sensitive files staged.
**On FAIL (wrong files staged):** `git reset HEAD <file>` to unstage, re-stage correctly.
**BLOCKED if:** Sensitive files (`.env`, credentials) would be staged — stop and report.

---

### A2 — Commit message passes all rules

Derive a commit message from the staged diff:

```bash
git diff --cached --stat
git diff --cached --name-only
```

Write a commit message following these rules — every rule is binary:

- [ ] First line ≤ 72 characters
- [ ] First line follows `<type>: <description>` format
  - Valid types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `style`
  - Description is lowercase, no trailing period
- [ ] No "Co-Authored-By" lines
- [ ] No "Generated by", "Claude", "Anthropic", or AI tool references
- [ ] No author name or email
- [ ] No task/issue/PR references in the subject line
- [ ] Describes WHAT changed and WHY, not HOW

**PASS:** All 7 sub-rules pass.
**On FAIL:** Rewrite the message until all pass.

Apply the commit:

```bash
git commit -m "<message>"
```

**PASS:** `git commit` exits 0.
**BLOCKED if:** Pre-commit hook rejects — fix the underlying issue, retry. Never `--no-verify`.

---

### A3 — Push to remote feature branch

```bash
git push -u origin HEAD
```

**PASS:** Push exits 0 and branch is on the remote.
**On FAIL (rejection):** Read the error. If remote diverged: `git pull --rebase origin <branch>`
then retry. If force-push is needed: BLOCK — do not force-push without explicit user approval.
**BLOCKED if:** Remote branch is `main` or `master` — stop and report.

### A4 — User approves the PR

**This assertion requires a human decision. It cannot pass without explicit user input.**

Show the user exactly what the PR will contain:

```
PROPOSED PR
───────────
Branch:  <current branch> → main
Title:   <proposed title>
Body:
  ## Summary
  <bullet points derived from diff>

  ## Test plan
  - All CI checks pass (ruff lint, ruff format, ty check, pytest)
  - <any manual steps>

Waiting for your approval. Reply APPROVE to create the PR, or CANCEL to stop here.
```

**PASS:** User replies with "approve", "APPROVE", "yes", or "y".
**BLOCKED:** User replies with anything else, or does not reply — do not create the PR.

Only proceed to PR creation after receiving explicit approval.

---

### A5 — PR created targeting main

Only run after A4 is PASS.

Check for an existing PR first:

```bash
gh pr list --head "$(git branch --show-current)" --base main --json number,url --jq '.[0]'
```

**If a PR already exists:** PASS — report its URL, skip creation.
**If no PR exists:** Create one using the title and body shown to the user in A4:

```bash
gh pr create --base main --title "<title>" --body "<body>"
```

**PR body rules:**
- [ ] No Claude, Anthropic, or AI tool references
- [ ] No author attribution
- [ ] Describes what changed and why

**PASS:** PR URL returned.
**BLOCKED if:** `gh` is not authenticated or remote is wrong — report exact error.

---

### A6 — Worktree cleanup (if applicable)

Detect whether we are in a worktree:

```bash
git rev-parse --git-dir
```

**Not a worktree** (output is `.git`): PASS — nothing to clean up.

**Is a worktree** (output contains `worktrees`):

After PR is confirmed open (A5 PASS), clean up:

```bash
WORKTREE_PATH=$(git rev-parse --show-toplevel)
MAIN_REPO=$(git worktree list | head -1 | awk '{print $1}')
git -C "$MAIN_REPO" worktree remove "$WORKTREE_PATH" --force
```

**PASS:** `git worktree list` no longer shows this worktree path.
**BLOCKED if:** Uncommitted changes remain — ensure A2 commit is complete first.
